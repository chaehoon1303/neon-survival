## 변경 전

1. `GAME_SPEC.md`에서 관련 게임 규칙을 확인한다.
2. `AGENTS.md`에서 저장소 규칙을 확인한다.
3. 전역 함수 래핑이나 `localStorage` 키에 영향이 있는지 검색한다.
4. 원본 웹과 `mobile-web/` 중 어느 범위가 대상인지 정한다.

## 구현 원칙

- 의존성 없는 바닐라 JavaScript와 Canvas 구조를 유지한다.
- 주무기 방향은 마지막 이동 방향, 자동 스킬만 적 추적이라는 규칙을 보존한다.
- 기존 저장 키와 저장 자료형은 호환성을 유지한다.
- `base.js`와 `modes.js`의 래퍼는 원본 호출과 반환값을 보존한다.
- 에셋을 추가하면 웹 원본과 모바일 스냅샷의 경로를 함께 확인한다.

## 검증

```bash
npm run check
```

이후 `npm run dev`로 다음을 수동 확인한다.

- 첫 실행, 상자 개봉, 장착, 전투 시작
- 이동 방향과 주무기 방향 일치
- 레벨업 카드와 일시정지/재개
- 스테이지/보스 전환 및 결과 화면
- 기지 보너스와 세 전투 모드
- 새로고침 후 코인, 장비, 진행도 복원

## 모바일 동기화

`capacitor.config.json`의 `webDir`은 `mobile-web`이다. 웹 원본 변경을 모바일 앱에도 출시하려면 대응하는 HTML/CSS/JavaScript와 에셋을 `mobile-web/`에 반영한 뒤 실행한다.

```bash
npm run ios:sync
npm run ios:open
```

<Note>
  현재 저장소에는 자동 복사 빌드 단계가 없다. `mobile-web/`은 독립 스냅샷이므로 누락 여부를 리뷰해야 한다.
</Note>
