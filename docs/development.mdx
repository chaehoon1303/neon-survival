## 변경 전

1. `GAME_SPEC.md`에서 관련 게임 규칙을 확인한다.
2. `AGENTS.md`에서 저장소 규칙을 확인한다.
3. 전역 함수 래핑이나 `localStorage` 키에 영향이 있는지 검색한다.
4. 원본 웹과 `mobile-web/` 중 어느 범위가 대상인지 정한다.

## 구현 원칙

- 의존성 없는 바닐라 JavaScript와 Canvas 구조를 유지한다.
- 주무기 방향은 마지막 이동 방향, 자동 스킬만 적 추적이라는 규칙을 보존한다.
- 기존 저장 키와 저장 자료형은 호환성을 유지한다.
- `base.js`와 `modes.js`의 래퍼는 원본 호출과 반환값을 보존한다.
- 에셋을 추가하면 웹 원본과 모바일 스냅샷의 경로를 함께 확인한다.

## 검증

```bash
npm run check
```

이후 `npm run dev`로 다음을 수동 확인한다.

- 첫 실행, 상자 개봉, 장착, 전투 시작
- 이동 방향과 주무기 방향 일치
- 레벨업 카드와 일시정지/재개
- 스테이지/보스 전환 및 결과 화면
- 기지 보너스와 세 전투 모드
- 새로고침 후 코인, 장비, 진행도 복원

## 모바일 동기화

`capacitor.config.json`의 `webDir`은 `mobile-web`이다. 웹 원본 변경을 모바일 앱에도 출시하려면 먼저 자동 동기화를 실행한다.

```bash
npm run mobile:web-sync
npm run ios:sync
npm run ios:open
```

<Note>
  `npm run ios:sync`는 `mobile:web-sync`를 먼저 실행하므로 HTML, CSS, JavaScript, 서비스 워커와 `assets/`가 빠지지 않는다.
</Note>

### Android

Android 프로젝트는 Capacitor 7의 `@capacitor/android`를 사용한다. Android Studio의 Setup Wizard 또는 SDK Manager에서 Android SDK Platform, Build-Tools, Platform-Tools, Emulator와 Command-line Tools를 먼저 설치한다.

네이티브 앱은 `@capacitor/screen-orientation`으로 실행 시 `landscape` 방향을 잠근다. 플러그인을 추가하거나 버전을 바꾼 뒤에는 iOS와 Android를 다시 동기화한다.

Gradle 빌드는 JDK 17~23을 사용하며 JDK 21을 권장한다. `scripts/android.mjs`는 `JAVA_HOME`과 macOS Homebrew JDK 21 경로를 확인해 호환되는 JDK를 자동 선택한다. Android Studio 2026에 포함된 JDK 25는 현재 Gradle 8.11과 호환되지 않으므로 빌드에 사용하지 않는다.

새로 받은 저장소에서는 의존성을 설치한 뒤 Android 생성 프로젝트를 한 번 추가한다.

```bash
npm install
npm run android:add
```

이미 `android/`가 있는 로컬 환경에서는 다시 `android:add`를 실행하지 말고 동기화나 빌드 명령을 사용한다.

```bash
npm run android:sync
npm run android:build
npm run android:open
```

USB 디버깅 또는 무선 디버깅으로 연결된 실제 휴대폰이나 준비된 에뮬레이터에서 바로 실행하려면 다음을 사용한다.

```bash
npm run android:run
```

`android/`는 Capacitor가 생성하는 네이티브 프로젝트이므로 직접 커밋하지 않는다. 웹 원본, `mobile-web/`, `capacitor.config.json`, `package.json`을 기준으로 필요할 때 다시 생성·동기화한다. SDK와 JDK는 머신별 로컬 도구이며 Git에 커밋하지 않는다.

macOS에서 `android:open`은 한글이 포함된 저장소 경로를 Android Studio 런처가 잘못 해석하는 문제를 피하기 위해 영문 임시 작업 폴더에서 IDE를 실행한다. 실제 Android 프로젝트 위치는 바뀌지 않는다.

## 웹 업데이트와 GitHub Pages

게임은 실행할 때 CSS와 JavaScript에 새 캐시 키를 붙이고, HTTP/HTTPS에서는 네트워크 우선 서비스 워커를 등록한다. 따라서 이미 접속했던 기기도 페이지를 다시 열면 최신 배포 파일을 우선 요청한다.

`main` 브랜치에 변경을 푸시하면 `.github/workflows/pages.yml`이 배포 전용 `_site/`를 만든 뒤 GitHub Pages에 자동 배포한다. 로컬 파일만 수정한 상태는 다른 기기에 전달되지 않으므로 공유 전에는 반드시 커밋과 푸시가 필요하다.

```bash
npm run pages:build
```
